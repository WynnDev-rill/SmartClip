# SmartClip

SmartClip is migrating from a server-backed web application to a private, Android local-first video highlight application. The goal is fully on-device processing without paid or AI APIs, cloud processing, or a runtime server requirement.

> **Current status:** Android can select one local video and read its metadata entirely on-device. FFmpeg, analysis, clipping, subtitles, and export are not implemented yet.

## Architecture

- `frontend/` contains the reusable React 19 + Vite + TypeScript + Tailwind interface and Capacitor configuration.
- `frontend/plugins/local-video-picker/` is a small Capacitor Android plugin. It opens Android's Storage Access Framework and reads metadata with `MediaMetadataRetriever` and `ContentResolver`.
- `frontend/android/` is generated by Capacitor locally or in CI and is intentionally ignored. Its application ID is `com.wynndev.smartclip`; Capacitor packages `frontend/dist`, and there is no remote `server.url`.
- `backend/` contains the existing FastAPI upload and `ffprobe` service. It is **transitional**, is preserved for browser development, and is not part of the final Android runtime architecture.
- `docs/android-architecture.md` contains the current-state audit, target design, reuse/replacement map, risks, and phased migration plan.

The Android build requests no internet, storage, camera, or microphone permissions. It is portrait-oriented and the React shell accounts for status-bar, cutout, navigation-bar safe areas, and 320px-wide screens.

## Local video selection

Tap **Choose Video** to open Android's system document picker, which includes compatible gallery and file-manager providers. The picker is limited to MP4, MOV, MKV, and WEBM video MIME types. SmartClip receives a `content://` URI and queries the provider for the display name, byte size, and MIME type; Android's native `MediaMetadataRetriever` reads duration, dimensions, and rotation. Rotation is applied to the displayed width and height before the orientation label is calculated.

Content URIs are used because modern Android providers do not have to expose a direct filesystem path. SmartClip never resolves the URI to a path and never uploads or copies the video. It requests a persistable, read-only URI grant so later local processing can reopen the selection after activity or app recreation. Provider support varies: a provider that does not offer a persistable grant may keep access only for the current session.

No broad storage permission (`READ_MEDIA_VIDEO`, `READ_EXTERNAL_STORAGE`, or `MANAGE_EXTERNAL_STORAGE`) is declared. Access is explicitly granted by the user for the single document selected through the system picker. Cancellation, denied access, unreadable media, unsupported extensions, and missing required metadata are presented as user-facing errors.

## Browser development

Prerequisites are Node.js 22+ and Python 3.11+.

```bash
cd backend
python -m venv .venv && source .venv/bin/activate
pip install -e '.[dev]'
uvicorn app.main:app --reload

# another terminal
cd frontend
npm ci
npm run dev
```

Open <http://localhost:5173>. The browser fallback uses a normal file input and the browser's video element to preview basic duration and dimensions. It does not call FastAPI, and its result is clearly labelled **Browser preview** because codec/container support and metadata fidelity vary by browser. Object URLs are released when a selection is replaced or removed.

## Build Android locally

Install Node.js 22, Java 21, Android SDK platform 35, and a configured `ANDROID_HOME`, then run:

```bash
cd frontend
npm ci
npx cap add android           # one-time generation of the ignored native project
npm run android:sync          # builds Vite and runs `cap sync android`
npm run android:build:debug   # syncs and runs Gradle assembleDebug
# optional: npm run android:open
```

The debug APK is generated at:

```text
frontend/android/app/build/outputs/apk/debug/app-debug.apk
```

## GitHub Actions debug APK

The **Android debug APK** workflow validates every pull request and can be started from **Actions → Android debug APK → Run workflow** using `workflow_dispatch`. After the job succeeds, open its run summary and download the **SmartClip-debug-apk** artifact. It contains the unsigned-for-release debug APK at the path above; no signing key or release is created.

## Current limitations and next step

Metadata availability depends on the selected Android document provider and the platform's container/codec support. Some cloud-backed picker providers may need to download content internally before exposing it, and providers may decline persistent URI grants. Browser metadata is a development convenience, not a substitute for Android-native results. SmartClip does not yet trim, render, analyze, or export media, and the transitional FastAPI backend remains in the repository but is not called by this UI.

The next product step is **local manual trimming and MP4 export**, operating directly from the persisted content URI without uploading the source.
